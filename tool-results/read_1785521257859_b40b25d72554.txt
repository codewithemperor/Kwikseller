   160→### How the layout is wired (investigation)
   161→
   162→The root layout (`src/app/layout.tsx`) wraps **every** route in
   163→`<MarketplaceLayout>{children}</MarketplaceLayout>` (inside Suspense +
   164→providers). `MarketplaceLayout` is a client component that already conditionally
   165→hides its header (`hideTopNav`) for cart/auth/vendor-storefront routes, and
   166→conditionally hides ALL chrome (footer, mobile nav, floating widgets) for vendor
   167→storefront routes (`isVendorStorefrontRoute`). The `(auth)` route group has its
   168→own layout but is still wrapped by MarketplaceLayout — the header is just hidden
   169→via the `hideTopNav` flag.
   170→
   171→This means a route-group `(account)/layout.tsx` alone would NOT suffice — the
   172→root-level MarketplaceLayout would still render its header/footer around the
   173→AccountLayout. The MarketplaceLayout MUST be taught to skip its chrome for
   174→account routes. Given that constraint, per-page wrapping is the safest approach
   175→(no folder moves, no import-path risk, no route-segment conflict between
   176→`(account)/orders/page.tsx` and `orders/[id]/page.tsx`).
   177→
   178→### Approach chosen: per-page wrapping + MarketplaceLayout flag

  1142→### 1. CRITICAL BUG FIX — `'client-only' cannot be imported from a Server Component module`
  1143→**Root cause**: `packages/utils/src/toast.ts` imported `toast` from `@heroui/react` at the top level. `@heroui/react` re-exports the `client-only` package, which Next.js's bundler detects and refuses to evaluate in a Server Component module graph. Since `toast.ts` was re-exported via `packages/utils/src/index.ts` (`export { kwikToast } from "./toast"`), any Server Component that imported anything from `@kwikseller/utils` (e.g. `app/layout.tsx` importing `AuthProvider, HeroUIProviderWrapper`) was pulling `@heroui/react`'s client-only marker into the server graph → HTTP 500 on every page.
  1144→
  1145→**Fix** — `packages/utils/src/toast.ts`:
  1146→- Added `'use client';` directive at the top of the file. This tells Next.js to only bundle this module (and its `@heroui/react` dependency) for the client, keeping the server module graph clean.
  1147→- The `kwikToast` helper is only ever called from event handlers inside client components, so the `'use client'` directive is semantically correct.
  1148→
  1149→**Fix** — `apps/marketplace/src/components/layout/toast-provider.tsx` (NEW, ~24 lines):
  1150→- Created a client-only wrapper around HeroUI's `Toast.Provider` so `app/layout.tsx` no longer needs to import `Toast` directly from `@heroui/react`.

  1299→## Known Issues / Risks
  1300→- **Sandbox memory (4GB)**: Same persistent issue — Next.js 16 dev server (webpack or turbopack) is OOM-killed after 1–2 page compiles. Each page compile takes ~20s and uses ~1.5GB RSS. Mitigation: `NODE_OPTIONS="--max-old-space-size=1536"` + clear `.next` before each restart + test pages one-at-a-time.
  1301→- **Dev server lifecycle quirk discovered this cycle**: When using `nohup setsid bash -c '...'` to start the server, it dies silently within ~1s of the parent bash exiting. Workaround: use plain `&` + `disown` (no setsid/nohup) — the server stays alive within the parent bash session. Across separate bash invocations the server may die; testing must be done within a single bash invocation.
  1302→- **Pre-existing TypeScript errors**: ~30 errors in files I did NOT touch this cycle (`order-progress-bar.tsx`, `order-actions.tsx`, `categories/page.tsx`, `search/page.tsx`, `enhanced-search-overlay.tsx`, `profile/page.tsx`, `orders/[id]/track/page.tsx`, `vendor/[slug]/checkout/page.tsx`, `data/products.ts`). These were present at the start of cycle 6 and are out of scope.
  1303→- **Helpful votes are session-only**: The `votedReviews` state is React state, not persisted. A page refresh resets the votes. A future cycle could persist these to `localStorage` or send them to the API.
